§1

Overview

Many users already trade a manual, indicator-based strategy by eye. This feature turns that into a strategy that runs itself on Nubra Cloud — Nubra's existing Python-code execution infrastructure — without the user writing a line of code. They answer guided questions, review a plain-language summary of what the system understood, correct it if needed, and only then deploy. See §4 for the flow, §5 for how it's built.

§2

Goals & non-goals

Goals

  • Describe a manual strategy, get back deployable code — no code touched.
  • Resolve ambiguity via guided + adaptive questions, not a long form or raw free text.
  • Real-money consequence is explicit — confirm a plain-language summary, never the code.
  • Reuse Nubra Cloud as the execution target; scope ends at a successful handoff.

Non-goals (v1)

  • Not a strategy marketplace or sharing feature.
  • Not live-strategy monitoring/pause/stop — Nubra Cloud's existing surface.
  • Single- and multi-leg/options on one underlying; not exotic custom payoffs.
  • Regulatory/compliance build-out. Out of scope — §15

User flow

#StepWhat happens
1NudgeFires on indicator-apply, or for a flagged regular trader (trade frequency + existing chart indicators). Toast at the moment + a standing panel entry.
2Card FlowFirst card picks single- vs. multi-leg; fixed questions follow, repeating per leg. Pre-fills from indicators already on the chart.
3MCQ LoopRemaining gaps become AI-generated MCQs (+ "Other"). No progress UI shown. A contradiction surfaces as another question here, not a block.
4GenerateStrategy Spec → Python matching Nubra Cloud's contract, plus a chart backtest preview run against recent history. Exact contract — §14 Rolling-average timer shown.
5ReviewPlain-language summary and a chart with the indicator plotted + entry/exit markers from the backtest preview — never code. Comment box is the only edit path — feedback loops back into Generate.
6DeployHandoff to Nubra Cloud. Scope ends here — no status link-back into this flow.
§5

Architecture

The authoring experience sits entirely in front of Nubra Cloud, reached once, at Deploy.

  • Both capture stages write into the same Strategy Spec via the Completeness Checker.
  • Review's comment box is the only way back into the Code Generator — the dashed edge.
  • The Backtest Engine reads the same Strategy Spec and feeds its chart straight into Review — a visual, not a statistical backtest. v1 scope — §14
  • Nubra Cloud is reached exactly once, at Deploy. Exact handoff contract — §14
§6

Design spec

ScreenKey behavior
NudgeCompact, dismissible, single CTA. On-chart toast at the triggering moment and a persistent panel entry — never blocks chart interaction.
Guided Card FlowOne question/card, large tap targets. First card: leg count — multi-leg repeats the set with an "add another leg" step. Pre-fills from the chart's live indicators. Progress = fields captured vs. needed, per-leg and overall.
Adaptive MCQ LoopSame card shell as above, so it reads as one continuous flow. Every MCQ has an "Other" free-text option. No round counter. A contradiction becomes the next question, in-context (e.g. "stop loss is above entry — which did you mean?").
Code generationSingle wait screen, rolling-average timer. No cancel affordance.
Review & confirmationPlain-language summary and a chart backtest preview — the configured indicator plotted on recent price history with markers at every bar the strategy would have entered/exited. Never code. Explicit real-money warning. Comment box is the only edit mechanism; feedback re-triggers this same screen with a new summary and a re-run preview.
Deploy confirmationSuccess state confirming handoff; outbound courtesy link to Nubra Cloud's own monitoring surface.

§8

Backend spec

ComponentResponsibility
Completeness CheckerQualitative rule set (fields present, mutually non-contradictory, per leg + overall) → ready/not-ready + gap list.
MCQ GeneratorNext targeted question from the gap list, or a contradiction-resolution question. Gap prioritization — §14
Code GeneratorStrategy Spec → Python, composing all legs into one strategy. Leg-combination semantics — §14
Feedback InterpreterReview comment → Strategy Spec diff → regenerate, version increments.
Backtest EngineStrategy Spec + recent historical price data → entry/exit markers for the chart shown on Review. Re-runs whenever the spec changes via feedback. Lookback window length, instrument-availability edge cases — §14
  • Round cap: 8 rounds (§12); past it, remaining gaps become Review callouts instead of blocking further.
  • Contradictions: resolved as another MCQ-style question — mid-flow during capture, or as a follow-up before regenerating if raised via Review feedback.
  • Backtest preview: visual only in v1 — entry/exit markers on a chart, not a statistical backtest (no win-rate, avg-return, or drawdown numbers). Whether to add those numbers later — §14
  • Nubra Cloud handoff: code + Strategy Spec metadata handed off; treated as an external system at interface level. Exact contract, auth, status handling — §14
  • Persistence: every answer/feedback round written immediately, not batched.
§9

Data model

Nine entities. StrategySpec is versioned and holds legs[] — length 1 for single-leg.

Every arrow is "one has many." Leg and Condition carry multi-leg/options strategies; leg_combination (synced vs. independent leg timing, net vs. per-leg stop/target) is still open — §14. BacktestPreview is new for the chart backtest step — visual markers only, not statistical metrics, in v1.

  id, user_id         uuid
  status              enum(card_flow, mcq_loop, generating, review, deployed, abandoned)
  source_context      jsonb   -- chart state at nudge time, for pre-fill
  mcq_round_count     int     -- capped at 8, §12
  created_at, updated_at timestamp
CardAnswer
  id, draft_id (fk)   uuid
  field               string   -- 'strategy_type', 'leg_1.stop_loss', ...
  raw_value           jsonb

  id, draft_id (fk)   uuid
  round_num           int

  version             int

Edge cases & failure handling

CaseHandling
Abandons mid-flowDraft persists server-side, resumable at any stage
MCQ loop doesn't convergeFalls through to Review with named gaps + comment box
Generation fails/times outExplicit failure + retry; no data lost
Contradictory answersAnother MCQ-style question, never silently resolved
Two legs conflictSame mechanism — a clarifying question naming both legs
Strategy shape unsupported by Nubra CloudMust be caught before Review §14
Feedback contradicts earlier answersTreated as an update — spec version increments
No historical signals in the lookback windowChart still renders with the indicator plotted; explicit "no matches in this window" state, not an error
Instrument lacks enough historical data for a previewBacktest chart step is skipped with an explicit note; Review still shows the plain-language summary §14
Repeated nudge dismissalNo suppression needed — tied to each new indicator applied
§12

Non-functional notes

  • MCQ round cap: 8, tunable default.
  • Generation timer: rolling average of recent durations. Bucket by complexity? — §14
  • Persistence: every answer written immediately, no batching.
  • Resumability: a refresh must not lose progress at any stage.
  • Concurrency: no app-level cap; Nubra Cloud capacity limits surface as a handoff failure (§11).

§15

Out of scope (v1)

  • Strategy marketplace / sharing between users
  • Live monitoring, pause/stop, lifecycle UI — Nubra Cloud's existing surface
  • Exotic/custom option payoffs beyond standard multi-leg structures
  • Regulatory/compliance build-out — pre-launch dependency, not solved here
  • Statistical backtest metrics (win-rate, avg-return, drawdown) beyond the chart preview's visual markers — v1 is proof-by-chart, not a performance report
  • Cancel-mid-generation affordance

§1

Overview

Today, forming a view and acting on it are two disconnected steps: a user reads the chart themselves, then separately opens the order ticket to place a trade. This feature closes that loop — an Analyse with AI entry point on the chart generates a trade setup (direction, entry, stop loss, target, rationale) for whatever instrument is on screen, shows it inline without leaving the chart, and lets the user go straight from that setup into a pre-filled order ticket.

Two clickable prototypes exist for how the result is presented — see §3 — built to get a founder decision before committing engineering effort to one.

§2

User flow

  • User opens a chart.
  • An Analyse with AI entry point (chart + AI icon) sits in the TradingView toolbar.
  • User selects the analysis mode — Quick or Deep — defaulting to Quick.
  • User clicks Analyse with AI (or, on repeat runs, an explicit Go button).
  • The AI analyses the current instrument and generates a setup: direction, confidence, entry / stop loss / target, rationale, favourable factors, and risks.
  • The setup is shown inside the chart experience; Entry / Stop Loss / Target are also plotted directly on the candles, color-matched to the same labels in the setup text.
  • A [Buy/Sell] with this setup action opens the order ticket pre-filled from the setup — the user only reviews and places.

§4

Analysis modes

  • Quick — a single AI pass, faster output. Default mode.
  • Deep — two AI agents independently analyse the setup, then debate their views before producing one combined final output. Slower, more thoroughly cross-checked.
  • An ⓘ info affordance next to Deep explains this distinction on demand, so the main copy stays uncluttered.
  • Re-running analysis after the first pass is an explicit action (Go) — Quick/Deep are pure selectors and never auto-trigger a new run by themselves.

No usage data exists yet for a feature that hasn't shipped. The figures below are a reasoned estimate to size expectations, not a forecast commitment.

Annualizing October's partial run gives a current baseline of roughly 5,000–5,300 chart orders/month on Web — already climbing as a share of total orders, independent of this feature.

Modeled lift

  • This feature targets conversion, not traffic — it shortens the gap between viewing the chart and placing the order for users already there.
  • Assume 20–40% of chart viewers try the feature in month 1–2 (it sits prominently in the toolbar).
  • Assume a 10–25% relative conversion lift for that cohort, from the inline setup + pre-filled order ticket removing friction.
  • Net: (20–40%) × (10–25%) ≈ 2–10% lift on chart-order volume.
Net modeled range
+100 to +500 orders/month

Incremental Web orders in the first 1–2 months post-launch, nudging chart's share of total Web orders from ~12% toward ~13–14% — on top of existing organic growth.

Recommend validating with a 2–4 week A/B rollout once shipped, rather than treating this range as a committed forecast.
